# 知识库新增 / 修改引导流程

## 何时使用

- 用户说「记录一下 / 补充知识 / 新增文档 / 加到知识库 / 更新这条知识」等。
- 完成一次排障、重构或决策后，用户希望把经验沉淀到知识库。
- 任何要向 `AGENT.md`、`.ai_knowledge/`、`skills/` 写入或改动内容的操作。

## 核心原则

1. **先查重，后落盘**：不创建与现有知识重复的文档。
2. **按影响面定位**：全局知识进公共库，仅模块内有效就按功能层级下沉。
3. **路由必登记**：任何新文档必须从根 [AGENT.md](../../AGENT.md) 沿链接可达。
4. **统一模板**：知识正文一律从 [.ai_knowledge/templates/knowledge-doc.md](../../.ai_knowledge/templates/knowledge-doc.md) 复制填充。

## 流程总览

```
明确知识 → 查重 → 定位存放位置 → 新建/更新文档 → 登记路由 → 校验汇报
```

## 第 1 步：明确知识

动手前先与用户确认（信息已齐全则不问）：

- **知识内容**：要记录的规则 / 机制 / 步骤 / 术语是什么？
- **知识类型**：architecture（架构）/ conventions（规范约束）/ runbooks（操作手册）/ glossary（术语）/ skill（可执行技能）。
- **影响范围**：全局通用，还是仅某个模块 / 某条流程？
- **触发来源**：是新经验，还是对旧知识的修正？（修正则进入「修改已有知识」分支）

## 第 2 步：查重（必做）

沿知识库的真实路由全面排查，不允许跳过：

1. 读根 [AGENT.md](../../AGENT.md)，顺链接读取 `.ai_knowledge/*/README.md`、各模块 `AGENT.md`、`skills/README.md` 的全部索引表。
2. 用知识的**关键词与同义词**（含英文名、代码标识符，如 `file://`、`data-src`、`alpha`）对 `AGENT.md`、`.ai_knowledge/`、`skills/` 及各模块 `AGENT.md` 做全文检索。
3. 对照命中文档正文的「关键词」与「内容」小节，判定关系：

| 查重结果 | 处理方式 |
|---|---|
| 已存在且内容一致 | 不新增；告知用户位置，结束 |
| 部分重叠 | 优先**更新原文档**（补充/修订），并在两文档间加「关联」互链；只有主题明显不同才新建 |
| 与现有知识矛盾 | **不自动覆盖**，向用户列出冲突点，确认以新换旧还是并存 |
| 无重复 | 进入第 3 步 |

## 第 3 步：定位存放位置（按影响面决策）

```
这条知识是"AI 可按步骤执行的一类操作流程"吗？
  ├─ 是 → skills/<skill-name>/SKILL.md（从 skills/_template/ 复制）
  └─ 否 → 影响面是否跨模块 / 面向全体开发与 AI？
        ├─ 是（全局约束、整体架构、通用 SOP、术语）
        │     → .ai_knowledge/<类型>/
        └─ 否，仅单一模块内部
              → 下沉到功能层级（见下方规则）
```

**模块知识的功能层级规则：**

- 模块路由入口固定为 `src/<模块>/AGENT.md`（如 `src/three/AGENT.md`），正文文档放在该模块的 `docs/` 子目录，例如 `src/three/docs/<主题>.md`。
- 知识影响范围只覆盖模块内某个子层级时，继续下沉到**最近的共同层级**，由该层级的 `AGENT.md` 路由；层级入口尚不存在则从 [module-agent.md](../../.ai_knowledge/templates/module-agent.md) 复制创建。
- 知识一旦被两个及以上模块共用，立即上移到 `.ai_knowledge/`，原位置改为链接，禁止两份副本。

**定位结论必须向用户说明**：放在哪、为什么是这个层级；边界拿不准时先问用户再写。

## 第 4 步：新建 / 更新文档

1. 新建文档：复制统一模板 [.ai_knowledge/templates/knowledge-doc.md](../../.ai_knowledge/templates/knowledge-doc.md) 到目标位置，按用户提供的知识逐项填充，不得留空标题与分类；无内容的小节写「无」而非删除结构。
2. 新建技能：复制 `skills/_template/` 整个目录为 `skills/<skill-name>/`。
3. 文件命名：小写英文或短横线 / 简明中文主题词，见名知义（如 `offline-build.md`、`线段数据结构.md`）。
4. 内容要求遵循该分类 README 的「收录标准」：规范类必须有规则→原因→正反例；手册类必须有前置条件→步骤→验证→失败处理。

## 第 5 步：登记路由（漏登视为未完成）

| 文档落点 | 必须登记的位置 |
|---|---|
| `.ai_knowledge/<分类>/x.md` | 该分类 `README.md` 的索引表 |
| `skills/<name>/` | `skills/README.md` 的「已安装技能」表 |
| `src/<模块>/docs/x.md` | 该模块 `AGENT.md` 的路由表 |
| 新建模块 `AGENT.md` | 根 `AGENT.md` 的「模块入口」表 |
| 任意新文档 | 在正文「关联」小节补上与相邻知识的双向链接 |

## 第 6 步：校验与汇报

交付前自查：

- [ ] 从根 `AGENT.md` 出发，新文档 2 跳以内可达（模块内文档不超过 3 跳）。
- [ ] 所有相对链接路径正确、目标文件存在。
- [ ] 查重结论已处理，库内无同义重复文档。
- [ ] 模板小节完整，「最后更新」为当天日期。
- [ ] 知识放对了层级（公共库 vs 模块内）。

向用户汇报：查重结果 → 定位结论与理由 → 新建/更新/登记的文件清单。

## 修改已有知识（分支流程）

1. 第 2 步查重定位到原文档后，**原地更新**，不另建文件。
2. 标题或主题改变时，同步修改所有索引表与反向链接中的文字；文件移动时更新全部引用方。
3. 删除文档前先全文检索其入链，先清链接再删文件，并同步注销索引登记。
4. 更新后刷新文档内的「最后更新」日期。
